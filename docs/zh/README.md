## 这个仓库是什么

面向工程师的 **AI 会议记录（AI note-taker）系统设计笔记**，讨论「本机采集」这一类架构：

**采集 → 转写 → 结构化 → 知识库 → 分享 / Agent**

- 只有文档，没有产品代码；也不是任何产品的官方仓库。
- 文档采用 MIT 许可（见 [LICENSE](../../LICENSE)）。
- 不给任何系统报准确率数字；涉及录音合规的内容只讨论产品体验，不构成法律意见。

## 为什么是「本机采集」

主流 AI 会议记录分两种架构：

| | 机器人进会 | 本机采集 |
| --- | --- | --- |
| 参会名单 | 多出一个机器人 | 没有额外参会者 |
| 触发方式 | 读日历、自动进会 | 用户按下开始，或检测到会议软件后询问 |
| 平台依赖 | 每个平台单独接入 | 任何在电脑上出声的通话都能录，含线下会议 |
| 数据先落在哪 | 厂商服务器 | 用户电脑 |
| 纪要分发 | 常默认发给所有受邀人 | 用户点名才分享 |

本机采集解决的是「IT 不让机器人进会」「纪要被群发」「笔记不在自己手里」这三类问题。它**不等于隐蔽录音**：没有机器人不代表对方不知道，用户仍然要告知参会者，产品应在第一次录音前提醒。

## 实例：Audiee.ai

文中以 [Audiee.ai](https://audiee.ai) 作为一个真实的 Mac 实现来说明设计取舍：

- 从 Mac 的系统音频和麦克风采集，不进会；自动识别 Zoom、Google Meet、Teams、飞书，其他通话（腾讯会议、钉钉、微信通话、线下会议）按 Ctrl+M。只在用户按开始时录，不读取别人的日历邀请。
- 默认「混合」模式，一句话里中英粤来回切也照样转写；粤语逐字稿保留口语和语气词，摘要用书面语。泰语、越南语、印尼语、马来语、菲律宾语夹英文也能记。
- 逐字稿和笔记是用户 Mac 上的 Markdown 文件，一键导出，删掉 App 文件还在；不用用户数据训练模型。
- 音频会上传到新加坡的语音服务转写，服务器不保留音频和逐字稿副本。笔记在本机，音频为转写上云，两句话都要说清楚。
- 分享要用户输入对方邮箱，对方收到只读链接；每人一个链接，可要求邮箱验证码，可设 7 / 30 / 90 天过期，随时撤回。默认不发给任何人。
- 本机 MCP 服务，安装后自动接好 Claude Desktop、Claude Code、Cursor。
- 免费版每月 3 小时转写（会议和语音输入共用）、20 场会议，知识库不限；阅读、搜索、提问、分享、MCP 不计量。付费方案见[价格页](https://audiee.ai/pricing)。
- 新加坡小团队，遵守 PDPA，没有第三方安全审计。详情见[信任页](https://audiee.ai/trust)。
- 仅支持 macOS 13 及以上，Apple 芯片和 Intel 都可以。

第一次录音前，Audiee 会提醒用户告知参会者。它不是绕过公司规定的工具；和 IT 的沟通仍然要做，信任页就是为这段对话写的。
